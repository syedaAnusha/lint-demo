Always format commit messages following the Conventional Commits specification.

Format: type(scope): description

Valid types:

- feat: a new feature
- fix: a bug fix
- chore: maintenance, dependencies, config changes
- docs: documentation changes
- refactor: code restructuring without behavior change
- style: formatting, missing semicolons, whitespace
- test: adding or updating tests
- perf: performance improvements

Rules:

- type must be lowercase
- description must be short and in present tense ("add" not "added")
- no period at the end of the description
- scope is optional but recommended

Examples:

- feat(auth): add Google OAuth login
- fix(upload): handle network drop during file upload
- chore(deps): upgrade Next.js to 15.1.0
- style(header): fix inconsistent spacing in navbar
